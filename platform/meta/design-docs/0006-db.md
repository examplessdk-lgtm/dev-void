# Database DX

**Date:** 2026-02-17
**Status:** Implemented

---

## Summary

Two features implemented that provide ORM-like DX without requiring an ORM:

### 1. Schema-Derived Types from Migrations

The routing plugin replays all `CREATE TABLE`, `ALTER TABLE`, and `DROP TABLE` statements from `migrations/*.sql` to build a final schema, then generates `.void/db.d.ts`:

```sql
-- migrations/001_create_users.sql
CREATE TABLE users (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL,
  email TEXT NOT NULL,
  created_at TEXT DEFAULT (datetime('now'))
);
```

Generates `DbTables` (read types) and `DbInsertTables` (insert types with optional columns for PK/DEFAULT). Updates on file save via the same file-watching infra as `routes.d.ts`.

SQLite type mapping: `INTEGER` → `number`, `TEXT` → `string`, `REAL` → `number`, `BLOB` → `ArrayBuffer`. Columns nullable unless `NOT NULL`. `PRIMARY KEY` implies `NOT NULL`.

### 2. Typed Query Helper (`void/db`)

Thin wrapper over D1 using generated `DbTables`/`DbInsertTables` for compile-time type checking:

```ts
import { db } from 'void/db';

const users = await db.list('users'); // Row<"users">[]
const user = await db.get('users', { where: { id: 1 } }); // Row<"users"> | null
await db.insert('users', { name: 'Bob', email: 'b@b.com' }); // type-checked columns
await db.update('users', { set: { name: 'Robert' }, where: { id: 1 } });
await db.delete('users', { where: { id: 1 } });
const n = await db.count('users', { where: { email: 'b@b.com' } });
const raw = await db.raw(
  'SELECT u.*, COUNT(p.id) as c FROM users u LEFT JOIN posts p ON p.user_id = u.id GROUP BY u.id',
);
```

The default `db` export uses `import { env } from "cloudflare:workers"` to access `env.DB` lazily — no need to pass `c.env.DB`. For explicit instances, use `createDb(database)`.

**Not an ORM.** No relations, no connection management, no migration system (that's separate). Complex queries (joins, subqueries, aggregates) use `db.raw()` or direct `c.env.DB`.

### Additional features

- **Column selection:** `db.list("users", { select: ["id", "name"] })` → `Pick<Row, "id" | "name">[]`
- **IN operator:** `{ where: { status: ["active", "pending"] } }` → `WHERE status IN (...)`
- **Multi-column orderBy:** `{ orderBy: ["status ASC", "created_at DESC"] }`
- **Count:** `db.count("users", { where: ... })` → `number`

## Design Decisions

- **No ORM integration.** ORMs are opinion-heavy — picking one alienates users of another. Nothing stops users from using Drizzle/Prisma today (`drizzle(c.env.DB)` works). We document how to bring your own ORM.
- **No comparison operators** (`gt`, `lt`, `like`, `between`). This is where APIs start bloating. `db.raw()` is the answer for complex queries.
- **No joins/aggregations.** Adding them means building half of Kysely. The API stays in the "zero learning curve CRUD helper" category.
