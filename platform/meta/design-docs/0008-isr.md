# ISR (Incremental Static Regeneration)

**Date:** 2026-02-17
**Status:** Implemented

---

## Summary

ISR fills the gap between SSG (fast but stale) and runtime SSR (fresh but every request hits the worker). Visitors always get a fast response; freshness is eventual (bounded by `revalidate` period).

---

## Architecture: Two-Layer Cache

```
Request
  │
  ▼
┌─────────────────────────┐
│   CF Edge Cache          │  Per-colo, ephemeral, fast
│   (caches.default)       │  TTL = revalidate seconds
└────────┬────────────────┘
         │ miss
         ▼
┌─────────────────────────┐
│   R2 (ISR store)         │  Global, persistent
│   {projectId}/isr/{path} │  Metadata: generatedAt, revalidate
└────────┬────────────────┘
         │ miss or stale
         ▼
┌─────────────────────────┐
│   User Worker (render)   │  Runtime SSR via dispatch namespace
└─────────────────────────┘
```

- **Edge cache** provides sub-ms response times per colo but is ephemeral
- **R2** provides single global source of truth — once any colo re-renders, all others read from R2
- Without R2, every cold colo hits the user worker; with R2, only the first global revalidation does

---

## Request Flow (dispatch worker)

1. Extract slug, KV lookup → routing entry (includes ISR config)
2. Build versioned cache key: `url + ?_v={version}`
3. **Edge cache hit** → return immediately
4. **R2 lookup:**
   - Fresh → serve from R2, cache at edge
   - Stale → serve stale immediately, `waitUntil`: re-render via worker → write to R2 + edge
   - Miss → render via worker (blocking), write to R2 + edge, serve

## User-Facing API

**Simple (uniform TTL):**

```ts
export const revalidate = 60; // all pages cached 60 seconds
```

**Per-path patterns (object form):**

```ts
export const revalidate = {
  '/': 60, // homepage: 60s
  '/docs/*': Infinity, // docs: cached until next deploy
  '/user/*': 0, // user pages: never cached (always SSR)
  '*': 30, // everything else: 30s
};
```

Rules matched in order — first match wins. `*` matches any characters including `/`. Special values: `Infinity` → cached until next deploy (1 year internally), `0` → always SSR.

**Per-response override (response header):**

The `defineRender` callback can set `x-revalidate` to override per-response:

- `x-revalidate: 0` — skip caching for this response
- `x-revalidate: 300` — cache 5 minutes instead of default

Only successful responses (2xx) are cached.

**`revalidate` without `prerender`:** Pure SSR + ISR caching. Cache populates lazily on first request to each path.

## On-Demand Revalidation

```ts
import { revalidate } from 'void/isr';

export const POST = defineHandler(async (c) => {
  await revalidate({ paths: ['/', '/blog/hello-world'] }); // purge specific pages
  // or: await revalidate({ all: true });                  // purge all ISR-cached pages
  return c.json({ ok: true });
});
```

Requires two env bindings:

- `VOID_PROJECT_ID` — automatically injected by the platform on deploy
- `VOID_REVALIDATE_TOKEN` — set via `void secret set`

Deletes R2 ISR entries. Edge cache expires naturally after `revalidate` seconds.

---

## Key Decisions

- **ISR entries cleared on deploy.** Versioned cache keys handle edge; R2 ISR entries cleared to avoid serving HTML referencing old asset hashes.
- **Error during revalidation:** Serve stale, log error, don't retry. Next request after `revalidate` seconds tries again.
- **ISR scope:** SSR pages only. API routes remain uncached.
- **Auth/personalized pages:** ISR skipped when request has `Cookie` or `Authorization` header, or response has `x-revalidate: 0`.
- **Thundering herd:** Not mitigated in v1. Future: revalidation lock via R2 metadata or KV.
