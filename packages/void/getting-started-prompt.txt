Void is a fullstack Vite framework and deployment platform for Cloudflare.
Void is currently in private preview. In an empty directory, set up a new app like this:

In the project, create `.npmrc` with this content:

@void-sdk:registry=https://npm.pkg.github.com

Then create a GitHub classic PAT with read:packages:

https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens#creating-a-personal-access-token-classic
https://docs.github.com/en/packages/learn-github-packages/about-permissions-for-github-packages

Store the token in your user ~/.npmrc:

//npm.pkg.github.com/:_authToken=YOUR_GITHUB_PAT

Then install:

npm install -D void@npm:@void-sdk/void

Then run:

npx void init

In an empty directory, `void init` will add the matching Pages adapter and starter dependencies after you choose a framework.

During `void init`, first choose a Pages framework (React, Vue, Svelte, or Solid), then choose D1 for a zero-config, fully managed default or PostgreSQL if you already have Postgres infrastructure or expect heavier writes and more complex queries.

At the end of the interactive flow, `void init` can also log you in and link or create your Void project so your first deploy is just:

void deploy

Database workflow: define Drizzle tables in `db/schema.ts`, import `db` from `void/db` and tables from `@schema`. Use `void db push` to prototype (applies schema directly, no migration files). Use `void db generate` when ready to create production migration files in `db/migrations/`. `drizzle-orm` and `drizzle-kit` ship with void — no extra install needed. Scaffold new tables with `void gen model <name> [columns...]`.

Routing extras: configure static redirects/rewrites/fallbacks under `routing.redirects`, `routing.rewrites`, and `routing.fallbacks` in `void.json`, or use a Netlify-style `public/_redirects` file (`200!` = force rewrite, plain `200` = fallback). `public/_redirects`, `public/_headers`, and every `routing.*` rule fire during `vite dev` on every target (including the default target) so you can iterate without a deploy. For dynamic rewrites, call `c.rewrite(path)` inside a `defineMiddleware`; `c.originalUrl()` returns the pre-rewrite `URL` (or `null`), and `c.isRewritten()` flags re-dispatched hops so you can skip side-effectful work. Destination strings are typed via `RewriteDestination` for route autocomplete, and asset extensions (`.png`, `.css`, `.js`, etc.) throw `VoidAssetRewriteError` since runtime rewrites can't reach the static asset handler. See `docs/guide/edge/rewrites.md` for the full write-up.
